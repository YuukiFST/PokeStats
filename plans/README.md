## Batch 2 — 2026-09-01 — "half a bounce" (perf focus)

Stamped against working tree over commit `0b6331f` (uncommitted feature work:
items/types/natures routes, lazy routes, `dex.json`/`catalog.json` split).
Each plan's drift check names the files to diff before starting.

Target the user set: every interaction — first pixels at launch, tab switch,
results after typing — should land in **≤ ~150 ms** ("half a bounce"), and no
frame on the way there may be black or empty.

### Approach chosen (so a later audit does not re-litigate)

- **Startup:** native GDI shell painted from a window subclass before the
  WebView exists, WebView child hidden until JS reports a painted frame.
  Rejected: a splash-screen second window (adds a window switch flash),
  `visible:false` + `show()` on page load (still black until first compositor
  frame), or trying to make WebView2 itself faster (its ~300 ms init is the
  floor; hide it, don't fight it).
- **Boot payload:** defer `catalog.json` until a page needs it, drop fields no
  runtime code reads, ship one JS wave. Rejected: a Web Worker for JSON parse
  (parse is not the bottleneck; the request wave and dead work are), a
  binary/MessagePack dataset (too invasive for the gain), embedding the
  dataset into the JS bundle.
- **Lists:** `React.memo` rows + plain anchors + delegated navigation.
  Rejected: replacing TanStack Virtual (it is not the cost), replacing the
  router (too broad), rendering fewer rows (users want the whole list).
- **Tab switch:** prewarm chunks + `initialOffset` scroll restore. Rejected
  for now: keep-alive of inactive tabs with React 19.2 `<Activity>` — pages
  read route state through `useSearch({ from })`, so a hidden tab would read
  the active tab's state. Revisit only if switches are still > 100 ms after 007.
- **Teams:** memoize where the cost is, keep formulas untouched (golden tests
  are the guard).

### Findings considered and rejected (this batch)

- **Brotli-compressed embedded assets** (Tauri default): decompression of the
  ~400 KB JS+CSS is single-digit ms; not a boot factor. Don't turn it off.
- **`Intl.Collator` for the Dex sort** instead of `localeCompare`: absorbed
  into 006's presort (sorting once makes the comparator cost moot).
- **Sprite GIF → animated WebP**: real bandwidth win for Form detail, but the
  detail page is not on the "half a bounce" path and lists already use still
  PNGs (002). Deferred; candidate for a later batch.
- **Web Worker for dataset indexing** (`indexDex`): measured indexing is
  ~10–20 ms after JSON parse; a worker adds a structured-clone round trip of
  the same size. Not worth it.
- **Splitting `ThreatMatchup` counters into a Worker**: 008's memoization
  removes the repeated work; the single scoring pass per opponent (~10–30 ms)
  is acceptable once.
- **`sessionStorage` scroll writes as a standalone finding**: absorbed into 007.
- **Removing the fade from `SpriteThumb` everywhere**: only the list variant
  matters (006 creates `ListSprite`); detail/compare fades are cosmetic and stay.
- **`PageFallback` skeleton styling**: after 007's prewarm it is rarely seen;
  no plan.
- **Lazy-loading `formDetail`/`moveDetail` separately from list pages**:
  superseded by 005 (one JS wave) + 007 (prewarm).
- **~113 MB of ani GIFs embedded in the 121 MB exe** (audit PERF-BOOT-01):
  real for installer size, not for launch latency. The PE is demand-paged and
  the embedded asset table is a static array — no GIF byte is read until a
  `/sprites/ani/*` request. The measured 0–300 ms gap is WebView2 init (004),
  not I/O; the user reports the process itself opens fast. Defender's
  first-run scan of a new binary is one-time. Deferred as a distribution
  improvement (ship `ani/` as a Tauri `resources` folder or optional pack),
  not a "half a bounce" item.
- **Splitting `desc` text (moves 125 KB, items 38 KB) out of `catalog.json`**
  and **slimming `dex.json` list fields** (abilities/evo edges, ~100 KB):
  deferred. After 005 the catalog is off the boot wave, so `desc` costs
  nothing at launch; `dex.json` parse is single-digit ms. Both need a second
  artifact for the detail routes. Re-measure after 005 before planning.
- **Dynamic-importing the idle locale in `i18n.tsx`** (~10–20 KB minified):
  parse cost ≈ 1 ms inside an already-compressed chunk; the first language
  switch would gain a fetch. Not worth it.
- **`TeamAnalysis` recomputing `formsWithSets` + `suggestTeamAdditions` per
  filter change**: `formsWithSets` is a ~4k-Set pass (~0.5 ms); the scoring is
  one pass over 1,380 Forms per slider/checkbox change and is already memoized
  on its inputs. `bestSwapTargets`/`suggestImprovementPlan` (combinatorial)
  only run on a full team. Measure with the Performance panel before planning;
  if a filter change exceeds ~50 ms, the fix is `useDeferredValue` on the
  filter inputs plus a `setsByFormId`-derived `formsWithSets` on the dataset
  (007 adds `setsByFormId`).
- **`SpriteThumb` dataset subscription outside lists** (Form detail, Compare,
  Teams cards): 006 removes it from the list variant (`ListSprite`), where the
  fan-out is 25–40 rows; the remaining call sites mount a handful of thumbs
  and the staged-dataset notify happens at most twice per launch.

### What was not audited

- Security, dependencies, docs, and DX categories — the invocation was
  perf-focused. Previous batch (2026-08-30) notes still apply.
- macOS/Linux startup paths (`winpaint` is Windows-only; other targets keep the
  default Tauri window behaviour — 004 must not break their build).
- Memory footprint of keeping `sets`/`learnsets` in memory (~2.7 MB JSON →
  larger JS heap); not on the interaction path.

## Batch 1 — 2026-08-30 — startup dataset + sprites

Focus of this batch: **startup time** (dataset) and **Pokémon image load** (sprites).
Default selection (maintainer: follow the advisor recommendation): plans 001, 002, 003.
Route-level JS code-splitting (`src/App.tsx`) was **not** selected (it has since
been implemented independently; 005/007 now build on it).

### Dependency notes

- **001 then 002.** 002 assumes `spriteUrls(form, kind, base, manifest)` and `{ still?: boolean, ani?: boolean }` on the manifest.
- **003 is independent** of 001/002.

### Approach chosen

- **Sprites:** manifest of files that exist + local-only `<img src>`. Rejected: keeping remote CDN fallbacks, HEAD-probing every Form, or a user toggle for online art.
- **Lists vs detail:** still PNG (Showdown gen5) for thumbs; ani GIF for Form/compare/lightbox. Rejected: dropping animation entirely, or shipping 154 MB of GIFs into every list cell.
- **Dataset:** one `LoadedDataset` + `extrasReady`, not two hooks and not optional `sets` on the type.

### Findings considered and rejected

- Recalculating BST via `enrichment` instead of `calcBST` in the Dex: cheap arithmetic. (005 now removes `enrichment` from the boot payload for a different reason: nothing reads it.)
- Precomputing `defensiveProfile` for ~1.3k Forms on load: cheap vs JSON parse.
- Workspace tabs mounting multiple Dex lists: they do not; one `Outlet`.
- Sidebar `logo.png` at 144 px: negligible.
- **PERF-04 / `src/App.tsx` eager routes:** implemented independently after this batch.
- **PERF-05 as a standalone plan:** absorbed into 003 (`Promise.all` on extras).
